 GOAL
-------------------------------------------------------------------------------

 Build the Express.js REST API with every security control designed in, each
 one carrying a code comment naming its ASVS requirement ID.

 to answer by pointing at the code.

 TASKS - SECURITY CONTROLS (each with ASVS ID in a code comment)
-------------------------------------------------------------------------------

 [ ] [KIRO]    Password storage - Argon2id, params per ASVS Appendix C
                 ASVS 11.4.2
 [ ] [KIRO]    Password policy - min 8 (15 recommended), NO composition rules,
                 breach-list check
                 ASVS 6.2.1, 6.2.5, 6.2.12
 [ ] [KIRO]    Session tokens - opaque refresh token in __Host- cookie,
                 HttpOnly, SameSite, Secure; short-lived access token
                 ASVS 3.3.1, 3.3.4, 7.2.3
 [ ] [KIRO]    Token validation - algorithm allow-list, reject alg:none,
                 verify audience and expiry
                 ASVS 9.1.1, 9.1.2, 9.2.1, 9.2.3
 [ ] [KIRO]    Token rotation + reuse detection on refresh
                 ASVS 7.4.1
 [ ] [KIRO]    Central authorization middleware
                 ownership resolved FROM THE DATABASE, never from request body
                 ASVS 8.2.2, 8.3.1
 [ ] [KIRO]    Role-based function access (buyer / seller / admin)
                 ASVS 8.2.1
 [ ] [KIRO]    Input validation - Zod schema per route at the service layer
                 ASVS 2.2.1, 2.2.2
 [ ] [KIRO]    Mass-assignment guard - explicit field allow-lists
                 ASVS 15.3.3
 [ ] [KIRO]    Output minimisation - DTO mapping, never return ORM entities
                 ASVS 15.3.1
 [ ] [KIRO]    File upload - size cap, extension/content match via magic bytes,
                 image re-encode, random internal filename, non-executable store
                 ASVS 5.2.1, 5.2.2, 5.3.1, 5.3.2
 [ ] [KIRO]    Unique-item locking - SELECT ... FOR UPDATE in the order txn
                 ASVS 2.3.3, 2.3.4
                 *** This is the signature control of a vintage marketplace. ***
 [ ] [KIRO]    Anti-automation - per-IP and per-account rate limits on
                 auth / search / order / AI endpoints
                 ASVS 2.4.1, 6.3.1
 [ ] [KIRO]    Security headers via Helmet
                 HSTS, CSP, nosniff, Referrer-Policy, frame-ancestors
                 ASVS 3.4.1 - 3.4.6
 [ ] [KIRO]    CORS - fixed allow-list, not a wildcard
                 ASVS 3.4.2
 [ ] [KIRO]    Error handling - generic client message, detail to logs only,
                 last-resort handler
                 ASVS 16.5.1, 16.5.3, 16.5.4
 [ ] [KIRO]    Security logging - auth outcomes, authz denials, bypass attempts;
                 UTC timestamps; NO secrets or tokens logged
                 ASVS 16.2.1, 16.2.2, 16.2.5, 16.3.1, 16.3.2
 [ ] [KIRO]    Secrets - nothing in source; env locally, CI secret store beyond
                 ASVS 13.3.1
