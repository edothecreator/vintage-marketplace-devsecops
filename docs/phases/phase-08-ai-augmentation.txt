 GOAL
-------------------------------------------------------------------------------

 Two distinct AI integrations, for two distinct reasons.

 1. IN THE APPLICATION - an LLM listing-description generator.
    Purpose: brings OWASP LLM Top 10 into scope, which the brief requires
    (section 5.d) whenever the project uses AI/LLM features.

 2. IN THE PIPELINE - AI triage of security findings.
    Purpose: this is literally the project title. Without it the pipeline is
    a conventional DevSecOps pipeline, not an AI-augmented one.

 PROVIDER: Google Gemini, free tier
   gemini-2.5-flash-lite preferred (highest daily request allowance)
   Quotas are per PROJECT not per key, and reset at midnight Pacific.
   VERIFY actual limits in AI Studio - published figures changed repeatedly
   during 2025-26.

 TASKS - OWASP LLM TOP 10 CONTROLS
-------------------------------------------------------------------------------

 LLM01 PROMPT INJECTION
 [ ] [KIRO]    Never concatenate raw user text into the prompt
 [ ] [KIRO]    Use structured/parameterised prompting; separate system from user
 [ ] [KIRO]    Strip or neutralise instruction-like patterns in user input
 [ ] [KIRO]    Constrain input length
 [ ] [KIRO]    Abuse-case test: injected instruction does NOT change behaviour
                 *** this is Phase 09 demonstration V7 ***

 LLM02 INSECURE OUTPUT HANDLING
 [ ] [KIRO]    Treat model output as UNTRUSTED input
 [ ] [KIRO]    Sanitise before storing; encode before rendering   ASVS 1.3.1
 [ ] [KIRO]    Never render model output as raw HTML
 [ ] [KIRO]    Never pass model output into a query, shell or eval

 LLM06 SENSITIVE INFORMATION DISCLOSURE
 [ ] [KIRO]    Never send secrets, credentials or personal data to the model
 [ ] [KIRO]    Do not include other users' data in the prompt
 [ ] [KIRO]    Log prompts WITHOUT sensitive content            ASVS 16.2.5
 [ ] [KIRO]    Document what leaves our boundary and goes to Google
                 (the LLM provider is an external trust boundary in the
                 threat model - see Phase 01)

 LLM10 UNBOUNDED CONSUMPTION / COST ABUSE
 [ ] [KIRO]    Per-user rate limit on the AI endpoint           ASVS 2.4.1
 [ ] [KIRO]    Global daily cap below the free-tier quota
 [ ] [KIRO]    Hard max output token limit
 [ ] [KIRO]    Monitor usage against quota (Phase 07 dashboard panel)
 [ ] [KIRO]    Alert before quota exhaustion
                 NOTE: the free-tier quota makes this risk CONCRETE rather than
                 theoretical, which makes it a genuinely demonstrable control.

 NOTES
-------------------------------------------------------------------------------

 - The AI triage comment on a PR is the single most distinctive artefact in the
   project. It is what makes the pipeline "augmentee par IA" rather than just
   DevSecOps with an LLM feature bolted on. Make it good.

 - Be honest about limitations in the report: the model can be wrong, can
   hallucinate a fix, and must not be trusted to dismiss findings. Saying this
   explicitly is stronger than pretending otherwise, and it directly answers
   the brief's requirement to consider LLM risks.
