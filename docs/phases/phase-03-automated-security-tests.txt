-------------------------------------------------------------------------------
 GOAL
-------------------------------------------------------------------------------

 Write an abuse-case test suite where every test is named for the ASVS
 requirement it verifies.

 WHY THIS PHASE MATTERS MORE THAN IT LOOKS

 Two independent sources converge on this deliverable:

 1. Prates & Pereira define P3 as API, web application and unit testing with a
    security focus - explicitly DISTINCT from SAST (P1) and DAST (P2). At 56
    mentions it is the third most cited practice in the entire field.

 2. ASVS states that running an off-the-shelf scanner is NOT the same as
    automated verification, and that application-specific checks must be
    written for anything involving business logic or access control.

 This is also what makes the Phase 09 V5 demonstration possible: an IDOR that
 SAST and DAST both miss, caught by our own suite.
