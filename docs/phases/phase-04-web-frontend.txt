-------------------------------------------------------------------------------
 TASKS - SECURITY CONTROLS (ASVS V3 + V14)
-------------------------------------------------------------------------------

 [ ] [KIRO]    NO tokens in localStorage or sessionStorage
                 session handled by the __Host- HttpOnly cookie
                 ASVS 14.3.3
 [ ] [KIRO]    Never use dangerouslySetInnerHTML
                 if rich text is truly needed, sanitise with DOMPurify first
                 ASVS 1.3.1, 3.2.2
 [ ] [KIRO]    Render user content as text, not HTML (createTextNode/textContent)
                 ASVS 3.2.2
 [ ] [KIRO]    Content Security Policy verified in the browser
                 object-src none, base-uri none, no unsafe-inline
                 ASVS 3.4.3
 [ ] [KIRO]    CSRF defence consistent with the cookie strategy
                 SameSite + anti-forgery token or Sec-Fetch validation
                 ASVS 3.5.1, 3.5.2, 3.3.2
 [ ] [KIRO]    Client-side validation present for UX, but NEVER relied on
                 ASVS 2.2.2
 [ ] [KIRO]    Clear authenticated data from the client on logout
                 ASVS 14.3.1
 [ ] [KIRO]    Anti-caching headers respected for sensitive views
                 ASVS 14.3.2
 [ ] [KIRO]    No sensitive data in URLs or query strings
                 ASVS 14.2.1
 [ ] [KIRO]    External resources use Subresource Integrity, or are self-hosted
                 ASVS 3.6.1
 [ ] [KIRO]    Accessibility pass - semantic HTML, labels, keyboard navigation,
                 contrast. (Required by our own standards; note that full WCAG
                 conformance needs manual assistive-technology testing and
                 expert review, which is out of scope here.)
