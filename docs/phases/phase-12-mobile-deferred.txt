-------------------------------------------------------------------------------
 WHY THIS IS DEFERRED
-------------------------------------------------------------------------------

 The project brief requires a mobile application as part of the mandatory
 architecture. It is NOT being skipped.

 It is deferred because the pipeline is where the grade lives, and a complete
 web application with a fully evidenced pipeline is worth more than two
 half-finished clients with a thin pipeline.

 This file exists now so that the architecture decisions taken in Phase 01
 already account for a second client, and no rework is needed later.

 PLANNED STACK: React Native (Expo), reusing the same API contract and the
 same TypeScript types as the web front-end.

-------------------------------------------------------------------------------
 NOTES
-------------------------------------------------------------------------------

 - If time runs short, a reduced mobile client (browse + login + view orders)
   that is genuinely secure and genuinely scanned beats a feature-complete one
   that is neither. The brief rewards security depth over feature count.

 - A mobile binary ships to the user's device. Anything embedded in it is
   readable. This changes the threat model meaningfully compared to the web
   client and should be stated explicitly in the report.

 - Do NOT start this phase until Phase 11 evidence is complete. The risk this
   whole deferral is designed to avoid is ending up with two unfinished clients
   and an unevidenced pipeline.
